5. Merging Datasets Using 3 Different Functions

You can merge two dataframes together in R using a variety of functions.

  • right_join()

  • left_join()

  • merge()

left_join()

Left_join essentially tells R “Take everything from the left table, and bring in matching information from the right table when you find a match”. If there’s no match in the right table, the new columns get filled with NA (missing values). That’s why it’s called a left_join - it keeps ALL rows from the left-hand dataset.

Syntax: left_join(x,y, by = “column name”)

leftjoin_data <- left_join(clinical_data, 
                           demo_data,
                           by = "participant_id")

Your Turn: right_join()

right_join essentially tells R “Take everything from the right table, and bring in matching information from the left table when you find a match”. If there’s no match in the right table, the new columns get filled with NA (missing values). That’s why it’s called a right_join - it keeps ALL rows from the right-hand dataset.

Syntax: right_join(x, y, by = “column_name”)

merge()

You’re probably wondering “What’s the point of merge() if we already covered left_join() / right_join?”. Well, merge() is actually included in base R. So, if you don’t have tidyverse loaded in your session for some reason, you can use merge.

Syntax: merge(x, y, by = “column_name”, all.x = TRUE/FALSE, all.y = TRUE/FALSE)

Where

  • x: dataframe 1

  • y: dataframe 2

  • all.x = If set to TRUE, keep all things from dataframe 1

  • all.y = If set to TRUE, keep all things from dataframe 2

Other key differences

  1. How join types are “selected”: As you can see above, you can still do a left or right join using the merge function, you just specify it in either of the all.x or all.y arguments.
  2. Row Reordering: Unlike left_join or right_join, merge() automatically sorts the output dataset by the “by” column. So, for example, if you’re joining by participant_id, the newly merged dataset will be ordered by the participant_id.

Example: merge()

merged_data <- merge(clinical_data, demo_data,
                     by = "participant_id")

Since participant_id is already in order, no reordering happened.. but its something to keep in mind.

6. Reshaping Data - An Important Step for Future Data Visualization

Data visualizations are one of the most powerful things R can do. Sometimes, in order to create visualizations we want, we have to reshape how our data looks so R can read it correctly to make said visualizations.

You will either be going from wide format to long format or long format to wide format.

For example, let’s look at rehab_study.csv. baseline_score and followup_score live in two separate columns - this is wide format, and if we wanted to create something like a boxplot comparing across timepoints, we wouldn’t be able to do it in wide format. Our data would have to be in long format.

Why?

In ggplot2, the most commonly used R visualization package, aesthetics for your graph require a single categorical column for time point and a single numeric column for the value. Because baseline and follow up scores are spread across two columns, ggplot2 can’t easily plot them together.

To reshape your data from wide to long, you can use pivot_longer(). pivot_longer() collapses multiple columns into key-value pairs.

Example: pivot_longer()

Let’s pivot our data longer so that baseline and follow up are all under one categorical column called “timepoint”

clinical_data_long <- clinical_data %>%
  pivot_longer(
    cols = c(baseline_score, followup_score), #Columns to collapse
    names_to = "timepoint",         #Name for the column I want those columns collapsed to
    values_to = "score"             # Where I want those respective values to go 
  )

Notice how “Male”, “mALe”, “MaLe”, “M”, and “MALE” all represent the exact same thing but R sees them as 5 distinct groups.

To handle messy text like this, we can use two essential functions from the stringr package (which is part of tidyverse): str_detect() and str_extract().

Pattern Detection with str_detect()

str_detect() asks a simple TRUE/FALSE question: “Does this text column contain a specific pattern?”

Because it returns TRUE or FALSE, it works wonderfully inside filter() to keep specific rows, or inside mutate() to create binary flag column.

str_detect() Syntax

str_detect(string_column, “pattern”)

Example: Filtering for Degrees with str_detect()

Let’s filter our demo_data to find participants who hold any type of degree.

degree_holders <- demo_data %>%

Pattern Extraction with str_extract()

While str_detect() tells us if a pattern exists, str_extract() pulls out the matching text and puts it into a brand new column. If the pattern is not found, R fills in NA.

Syntax: str_extract(string_column, "pattern")

Cleaning Currency and Numbers with str_remove() and as.numeric()

All other examples were basically just filtering data examples, but cleaning up text strings is where most of these stringr packages come in handy. For example, numeric variables often come attached to symbols like $ or “,” (like our income columns).

Because R views “$60,000” as text/a string, we can’t calculate a mean or median until we clean it up. We can use str_remove() to strip unwanted symbols.

demo_clean <- demo_data %>% 
  mutate(
    income_clean = str_remove(income, "\\$"), # Remove the dollar sign
    income_clean = str_remove(income_clean, ","), # remove comma
    income_clean = as.numeric(income_clean) # treat as a number
  )
